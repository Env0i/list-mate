# 机会评估: list-mate — 个人 ACGN 媒体库

**提交者**: Alex (PM)
**日期**: 2026-05-18
**决策截止**: 2026-05-20

---

## 1. 为什么是现在？

用户目前完全没有记录 ACGN 消费轨迹的工具，靠大脑记忆，已产生实际困扰：
- "看过一集动漫但是没看完，后忘记进度" — 直接引述，每周发生
- 游戏玩过模组/整合包，下次重装不知道装了哪些 mod

这是一个"给自己用的工具"场景 — 不需要说服别人，解决自己的痛点就值得做。

技术层面：
- 已有目标技术栈（Uni-app + FastAPI）和两个项目经验（goal-mate, money_mate）
- Bangumi API 开放可用，零成本接入
- 数据本地存储，无服务器运维成本

**如果等 6 个月**：用户还会继续看番/读小说/打游戏，遗忘的痛会持续积累。

---

## 2. 用户证据

**直接对话引用**：
> "我现在没有记录，所以导致我现在很难受，不知道进度"
> "比如看过了一部动漫，但是我没有看完，后忘记进度等等"
> "关于游戏方面，我可能玩完本体后还可能打上不同的模组或者整合包，我还想记录这些"

**行为数据**：用户作为开发者，已有两个完整全栈项目（goal-mate, money_mate），证明有能力且有意愿自己造工具解决个人需求。

---

## 3. 方案范围

| 维度 | 范围 |
|------|------|
| 覆盖品类 | 动漫 / 小说 / 漫画 / 游戏（含子分类 + 游戏多配置）|
| 平台 | H5 Web + 移动端 App + 管理后台 |
| 数据源 | Bangumi API 自动填充 + 手动兜底 |
| 标记能力 | 自定义标签 / 评分(0-10) / 文字评价 / 模组清单上传 |
| 列表视图 | 卡片模式 + 列表模式 双视图 |
| 统计 | 分类分布 / 状态分布 / 标签频率 |

### 明确不做的

> 内置阅读器/播放器、社交/好友、多用户、第三方平台同步导入、推荐算法、AI 功能

---

## 4. RICE 优先级评分

| 因素 | 值 | 说明 |
|------|-----|------|
| Reach | 1 人 | 纯个人工具，n=1 |
| Impact | 3 | 解决真实每日痛点，频率高 |
| Confidence | 90% | 用户自己就是需求方+开发者，无需求不确定性 |
| Effort | 中 (M) | 估算: 后端 2-3天 + 移动端 3-4天 + 后台 2天 |
| **RICE** | **(1×3×0.9)÷M = 高分** | 个人工具不需要 ROI 论证，痛点足够痛即可启动 |

---

## 5. 方案对比

| 选项 | 优点 | 缺点 | 工作量 |
|------|------|------|--------|
| 从零自建（当前选项） | 完全自定义，技术栈熟悉 | 需要全栈开发时间 | M |
| 用现成 App（Sequel/Bangumi） | 即开即用 | 不适配游戏模组需求，不能自定义 | S |
| 用 MediaTracker 自托管 | 已有成熟功能 | 技术栈不符(JS)，改造成本高 | L |

**决策**: 自建。用户已有完整的技术能力和项目经验，且目标 App 的逻辑比其他两个 mate 项目更简单。

## 6. 推荐路线图
