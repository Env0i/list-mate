## 1. 问题陈述

### 痛点
用户消费动漫、小说、漫画、游戏四类媒体内容，但没有任何记录工具，导致：
- 忘记看到哪了（动漫第几集、小说第几章、游戏进度）
- 忘记看过什么（过段时间想不起某部作品的名字）
- 无法回溯自己的 ACGN 历程（一年看了多少、类型分布）
- 游戏打过模组/整合包后，下次重装想不起来之前装了什么

### 目标用户画像
**个人用户**，ACG 爱好者 + 游戏玩家，拥有多设备（手机 + 电脑），习惯：
- 看新番和补老番
- 读网络小说（起点/下载 txt）和轻小说
- 看漫画/条漫
- 玩单机/手游/主机游戏，会打模组和整合包

### 当前方案 vs 理想方案
| 维度 | 现状 | 目标 |
|------|------|------|
| 进度记忆 | 靠大脑，容易忘 | 随手记，随时查 |
| 作品库 | 分散在各个平台 | 统一管理 |
| 个人标记 | 无 | 自定义标签 / 评分 / 评价 |
| 游戏模组 | 无记录 | 每个配置独立追踪 + 清单文件 |
| 数据来源 | 手动 | Bangumi API 自动填充 |

## 4. 用户画像与故事

### 主要用户：ACGN 爱好者

#### Story 1：追番进度
> 作为一个上班族番剧爱好者，我想在每看完一集动漫后快速记录进度，这样下周打开时不用回忆看到第几集。

**验收标准**：
- [ ] 在详情页一键更新进度数值
- [ ] 进度自动递增（看一集点一下）
- [ ] 列表页显示"第 X 集 / 共 Y 集"

#### Story 2：网络小说阅读
> 作为一个网络小说读者，我想记录在读的《神秘复苏》看到第几章了，这样每次打开 txt 文件时知道从哪里继续看。

**验收标准**：
- [ ] 支持手动添加 Bangumi 搜不到的作品
- [ ] 小说进度单位支持"章"
- [ ] total 可空（连载中未知总章数）

#### Story 3：游戏多配置管理
> 作为一个老滚玩家，我装了本体、奇幻大修整合包、和自己乱打的模组，我想分别记录每个的进度和评分，并上传 mod 清单方便以后重装。

**验收标准**：
- [ ] 游戏作品下可创建多个游玩配置
- [ ] 每个配置独立：名称 / 进度 / 状态 / 评分 / 评价
- [ ] 支持上传 .txt 模组清单文件
- [ ] 作品详情页展示所有配置列表

#### Story 4：搜索添加作品
> 作为一个用户，我想搜索作品名称后系统自动填充封面、总集数、简介等信息，减少手动输入。

**验收标准**：
- [ ] 接入 Bangumi API 搜索
- [ ] 搜索结果展示封面缩略图 + 标题 + 类型
- [ ] 选择后自动填充编辑表单
- [ ] 搜不到的可以手动输入（跳过搜索）

#### Story 5：个人标记
> 作为一个有收藏癖的用户，我想给作品打上"神作""催泪""N刷"等自定义标签，并打分写评价。

**验收标准**：
- [ ] 自定义标签 CRUD（名称 + 颜色）
- [ ] 作品可关联多个标签
- [ ] 评分 0-10
- [ ] 文字评价
- [ ] 按标签筛选作品

#### Story 6：数据概览
> 作为一个喜欢看数据的用户，我想看到我的 ACGN 库统计：各分类有多少、各状态分布、标签频率。

**验收标准**：
- [ ] 仪表盘显示分类计数和状态计数
- [ ] 统计页有分类占比和状态分布
- [ ] 最近更新列表

## 5. 解决方案概述

### 架构
- **后端**: Python FastAPI + SQLAlchemy + SQLite（单用户本地运行）
- **移动端**: Uni-app 3.0 (Vue 3) → 编译为 H5 Web + iOS/Android App
- **管理后台**: Vue 3 + Element Plus（Web 端管理）
- **数据源**: Bangumi API（自动填充作品信息）

### 核心数据模型

```
Work（作品）
├── category: anime / novel / comic / game
├── sub_category: TV/剧场版/轻小说/网络小说/漫画/条漫/单机/手游...
├── progress_unit: ep/chapter/volume/page/percent
├── total: nullable（连载中留空）
├── bangumi_id: 可选，关联外部数据
│
├── Tag [M:N] — 自定义标签（名称 + 颜色）
│
├── Progress（通用进度记录—动漫/小说/漫画用）
│   ├── progress_value
│   ├── status: wish / watching / completed / paused / dropped
│   ├── rating: 0-10
│   └── review: 文字评价
│
└── GameProfile（仅游戏用—多配置）
    ├── name: 配置名（本体/整合包/自打模组）
    ├── progress_value / status / rating / review
    └── mod_list_file: 可选的模组清单 txt
```

### 核心业务流程

```
搜索作品 → Bangumi 检索 → 选择作品 → 自动填充 → 确认保存 → 管理/更新进度
```

**添加作品有两个入口**：
1. 搜索 Bangumi → 自动填充 → 确认保存（搜得到时）
2. 跳过搜索 → 手动填写 → 保存（搜不到时）

## 6. 技术考量

### 依赖
| 系统/组件 | 依赖 | 风险等级 |
|-----------|------|---------|
| Bangumi API | 网络连通性 | 低 — 搜不到时降级为手动 |
| SQLite | 本地文件读写 | 无风险 |

### 已知风险
| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| Bangumi API 变更 | 低 | 高 | 封装隔离层，可切换数据源 |
| 数据库文件损坏 | 低 | 高 | 考虑后续加备份导出 |
| Uni-app App 端兼容 | 中 | 中 | 先用 H5 验证，再编译 App |

### 开放式问题
- [ ] 是否需要分类默认标签预设（如看番用户常打的标签）？
- [ ] Admin 后台是否需要批量导入功能？
- [ ] 数据导出格式偏好？（JSON / CSV）
