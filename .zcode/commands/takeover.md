## 授权与边界

- 本地个人项目，无需备案/合规/安全加固，技术方案自行判断并给出理由

- 红线：不得删除/重置 backend/list_mate.db（含 -wal/-shm）；不得 force push；git push 前须经我确认

## 工作方式

1. 先读 AGENTS.md 和 CLAUDE.md 了解项目约定与设计决策，再动手
2. 大任务先用 TodoWrite 拆解出任务清单，按清单推进并随时更新状态
3. UI 改动完成后启动本地服务（后端 8000 / 前端 5173），用浏览器实际操作并截图验证，不允许只看代码就宣布完成
4. 后端改动必须跑通 api_full_test.py（脚本要求后端跑在 localhost:8001）；改行为要补测试
5. 每完成一个独立里程碑就 git commit，风格沿用现有：`类型: 中文描述`（Fix: / Refactor: / Docs: / Chore:）
6. 收尾时同步更新 task_plan.md 和 progress.md，让下一次接管有据可查
7. 只有无法从代码和文档推断的产品级决策（如两种交互形态二选一）才来问我，其余自己定
8. 完成后总结：改动清单、验证方式、遗留事项
